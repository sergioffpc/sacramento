# Gate 2G — final composed-foundation synthesis

Date: 2026-09-02

## Verdict

**Conditional pass for foundation feasibility. Production dependency admission
remains blocked.**

The selected narrow Sacramento-owned C++23 composition is
`conditionally_viable` for the initial Windows Trainee Client and Debian Session
Authority baseline. Gates 1 through 2F did not expose a controlling
incompatibility among the selected dependencies, target platforms, canonical
authority boundary, offline Map pipeline, literal network exchange, rendered
client, Acoustic Propagation seam, or observability profiles.

That is a prototype finding, not a production-admission finding. The evidence is
made of intentionally narrow proofs. In particular, the literal Gate 2F client
connects to the retained Gate 2C authority, while the authoritative PhysX and
Map-package proofs remain separate executables. The work does not constitute a
complete Reference Personnel Recovery Scenario vertical replay, an approved
Reference Workload Profile, or a security and recovery qualification.

Every selected item therefore retains the status `prototype_evidence_only`.
Issue #13 must decide whether this conditional viability and its explicit
exceptions justify confirming ADR-0003's selected strategy. It must not treat
this report as automatic production admission.

## Measured cost and coupling observations

These measurements come from different gates and machines or environments.
They must not be summed into an integrated build, storage, or performance
budget.

- The Falcor proof retains three versioned patches, a roughly 4.4 GiB populated
  Packman cache, a 128,400,221-byte immutable SDK archive, and a
  227,361,891-byte relocatable native Gate 2F bundle. The Gate 2F executable is
  8,834,048 bytes.
- The PhysX/Flecs authority executable is 5,889,576 bytes; its two clean
  consumer builds measured 4,139 ms and 4,146 ms.
- The Assimp cooker adapter is 1,615,176 bytes and the dependency-free runtime
  reader is 38,120 bytes. Clean builds measured 2,349 ms and 2,303 ms; identical
  clean cooks measured 62 ms.
- The GNS authority and client are 10,204,248 and 10,192,272 bytes. Clean
  project builds measured 3,654 ms and 3,652 ms; the fresh dependency closure
  took 6.5 minutes. At that gate, the first-party surface comprised 253 adapter,
  175 codec, 119 public-header, and 291 driver lines.
- Steam Audio dependency installation measured 71,446 ms for Debian and 56,187
  ms for Windows; application builds measured 2,048–2,200 ms. The adapter has
  364 lines and the Sacramento event/API seam another 260 lines.
- Tracy target packages measured 3,619,920 bytes on Debian and 3,329,702 bytes
  on Windows. Fresh application builds measured 1,639–1,955 ms. The Sacramento
  writer and private adapter contain 156 and 14 lines respectively.

The licence and dependency manifests retained by each gate are evidence inputs,
not a consolidated production SBOM or legal approval.

## Exception register

All five exceptions block production admission. Where marked as an owner
decision, issue #13 must accept the maintenance/support consequence or direct a
replacement.

- `EXC-FALCOR-VENDOR-CAPSULE` (owner decision): authorize maintained
  Vulkan-only Falcor patches and Packman only inside an integrity-controlled
  offline vendor capsule, or replace Falcor.
- `EXC-BUILD-TOOL-VERSIONS` (owner decision): reconcile repository CMake 4.2.3
  with vcpkg-required CMake 4.4.0 and seal every retained host helper, including
  GNU Make.
- `EXC-CROSS-VCPKG-PROFILE` (engineering admission work): create one supported
  production cross-vcpkg profile for find roots, Release `try_compile`, CRT,
  C++23, and reproducible clang-cl path maps.
- `EXC-VENDOR-SUPPORT-MATRIX` (owner decision): accept and own unsupported
  Clang 22/Debian 13 PhysX and Linux-hosted clang-cl Steam Audio/Tracy paths, or
  select supported versions.
- `EXC-GNS-CRYPTO-BACKENDS` (owner decision): approve and qualify OpenSSL on
  Debian plus BCrypt on Windows, or choose one cross-platform crypto dependency.
  Neither choice substitutes for AUTH Protected Exchange.

## Explicitly unproved obligations

The following obligations are deliberately preserved verbatim in the
machine-checkable synthesis so that a later decision cannot silently erase
them:

- Complete Reference Personnel Recovery Scenario vertical replay
- AUTH, Admission, offline trust, durable audit commit, continuity, and State Restoration
- Controlled LAN loss, congestion, reconnect, recovery, and 16-client stress
- Approved 16.67 ms presentation and 100 ms authoritative-action workloads
- Representative Evaluator visual and acoustic validity and peak coverage
- Real-time audio/device path, reflections, pathing, and stress behavior
- Live Tracy capture, profiling overhead, and complete production observability transport
- Candidate-wide vulnerability disposition, consolidated SBOM, and offline dependency reconstruction
- One patch-version upgrade with measured adapter churn
- Demonstrated ongoing maintenance within two concurrent human generalists

## Recommendation to issue #13

Confirm the selected strategy only as a conditional architectural direction:
Sacramento owns the canonical model, protocol, content package, authority,
observability contract, and vendor-neutral seams; the named third-party items
remain replaceable implementation mechanisms. Carry all five exceptions and ten
unproved obligations into the decision record. Keep production dependency
admission as a separate, blocked activity until its owners and acceptance
evidence exist.

This completes issue #11's prototype question because it gives every requested
evidence category an explicit disposition and states what the experiments can
and cannot support. ADR-0003 remains Proposed until issue #13 records the owner
decision.
